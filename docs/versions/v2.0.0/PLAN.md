## 1. 版本目标

V2.0.0 把 V1.5.0 已验收的本地后端能力做成普通用户可以连续完成的图形产品。正式便携发行包必须让用户无需安装 Python / Node.js、无需打开终端或 Swagger、无需编辑 `.env`，即可完成：

~~~text
启动便携应用
→ 首次设置当前豆包 / 火山方舟连接
→ 初始化或升级数据库并检查索引
→ 上传 PDF、提取并维护 Experience
→ 输入身份信息与目标 JD
→ 分析 JD、选择模板、生成 DOCX
→ 查看告警或失败建议并下载文件
→ 在本地系统页执行状态检查、迁移、重建和失败重试
~~~

本版本只增加图形交互、支撑图形交互的薄 API、受控配置和便携运行能力。Experience / Fact、两层选材、受约束改写、Builder、Renderer、迁移和 Embedding 生命周期仍由现有后端服务负责；前端不得建立第二套业务规则或事实状态。

## 2. 已冻结的产品选择

1. **发行形态**：Windows 首发使用自带运行依赖的便携发行包和图形启动器，不以安装包为前提；源码开发入口继续保留。
2. **顶层入口**：只有“生成工作台” `/`、“履历库” `/profile`、“本地系统” `/system` 三个顶层页面；首次设置是受控引导流程，不新增第四个长期入口。
3. **配置输入**：Ark Base URL、API Key、LLM model 和 Embedding model 均由前端页面输入；浏览器不长期保存密钥。
4. **履历粒度**：首版页面只查看和操作 Experience；Fact 继续作为后端事实层，但不提供 Fact 展开、revision/hash 详情或独立编辑。
5. **视觉方向**：简洁、高级，以克制配色、清晰层级、充足留白和一致组件实现，不堆叠装饰、动画或复杂仪表盘。
6. **浏览器范围**：发布验收覆盖 Windows 桌面 Chrome 与 Edge；Firefox 和完整移动端适配不作为本版 PASS 条件。
7. **演示边界**：不提供普通用户零密钥 Stub 图形演示；现有 Stub Demo 只保留为开发和回归验证入口。

## 3. 强制架构与安全边界

### 3.1 页面与业务真源

- 前端采用 React + TypeScript + Vite；生产构建后的静态资源由 FastAPI 同源提供，开发服务器只用于开发；
- API Client 使用统一强类型封装，字段和错误与后端契约一致；
- 页面不得实现 Fact reconciliation、Embedding 状态推导、选材排序、来源校验、Builder 或 DOCX 渲染；
- 页面只把用户动作提交给后端，以后端确认响应作为最终状态；乐观展示不能冒充已保存；
- 用户输入、模型输出和错误文本按不可信文本渲染，禁止用 `innerHTML` 注入；
- 不在 `localStorage`、URL、前端日志或构建产物中保存完整履历、JD 或 API Key。

### 3.2 本地配置与密钥

- 首版只图形化当前已支持的豆包 / 火山方舟配置，不建立多 Provider、BYOK 平台或任意兼容协议；
- 浏览器通过写入型表单把 Key 传给本地后端；普通读取接口只返回“已配置/来源/脱敏末尾”等元数据，永不返回完整 Key；
- Windows 便携版的长期 API Key 必须进入 Windows Credential Manager 或等价操作系统凭据库；非密钥配置保存在 runtime data root 下的版本化配置中，不写入源码 checkout 或便携程序目录；
- `.env` 继续作为开发/自动化/故障恢复入口。有效配置必须由单一 resolver 解析并显示来源，禁止 UI、环境变量和模块级缓存各自形成不同真源；
- 连接配置按“填写候选 → 校验字段 → 测试 LLM / Embedding 能力 → 激活”执行。失败候选不能覆盖最后一个可用配置；
- LLM 配置变化只影响后续请求；Embedding model、Base URL 或维度/fingerprint 变化必须使旧向量明确失效，重建成功前阻断生成；
- 凭据库不可用、写入失败或删除失败必须显式失败，不得退回明文 SQLite、配置 JSON、日志或浏览器缓存。

### 3.3 本地管理接口

- 为页面增加配置、status、migrate、rebuild、retry 等受控 API；API 直接调用现有服务，不执行拼接 shell、任意命令、任意 SQL 或用户提交的本地路径；
- 服务必须只绑定 loopback，生产不启用任意来源 CORS；写操作校验 Host、Origin 和启动会话/CSRF 令牌，防止其他网页静默调用本机管理接口；
- 迁移、全量重建、重试与生成共享明确的并发门禁；冲突操作拒绝或排队语义必须冻结，不能同时改写同一数据库/索引；
- 数据库未创建、需要迁移或索引未就绪时，应用仍能进入受限设置/维护模式；业务生成保持禁用，不能为了显示页面而绕过就绪检查；
- 删除 Experience、迁移和全量重建需要页面确认；确认只授权精确操作，不产生通用命令执行能力；
- 所有失败返回可操作建议和脱敏诊断标识，不向页面返回堆栈、完整 Prompt、API Key 或本机隐私路径。

### 3.4 便携启动器与运行数据

- Windows x64 首版采用 PyInstaller `onedir` 目录型便携打包；如果实际依赖形成不可兼容阻断，开发 Agent 必须先在 RESULT 记录证据并请求调整 PLAN，不得静默切换为 `onefile` 或其他生命周期语义；
- 便携包包含后端运行时、前端静态资源、系统模板和必要依赖，不包含 `.env`、API Key、真实数据库、真实输出、缓存或开发者本机路径；
- 图形启动器负责启动 loopback 服务、等待健康检查、打开默认浏览器，并提供重新打开界面和退出应用的图形操作；不得显示要求用户操作的控制台窗口；
- 重复启动必须识别同一应用实例；端口被其他进程占用时不得误连，必须给出可操作错误或选择安全可用端口；
- 关闭/退出必须释放 HTTP listener、数据库 engine、后台线程、文件句柄、锁文件和临时资源；重复退出保持幂等；
- runtime data root 继续位于源码和便携目录之外。便携包移动、升级或删除不得删除用户数据；测试不得读写真实 runtime；
- 应用启动所用页面和会话令牌不得通过可复制的敏感 Token URL 暴露。

## 4. 页面与功能契约

### 4.1 首次设置与本地系统 `/system`

页面至少提供：

- 当前应用版本、服务和 runtime 状态；路径只显示必要的规范化摘要；
- Ark Base URL、API Key、LLM model、Embedding model 的输入、连接测试、激活和更新；
- 数据库状态、schema version、Experience/Fact/Embedding 汇总和明确下一步；
- 全新库初始化、既有 V1.5.0 库迁移、Embedding 全量重建、失败项重试；
- 操作进行中、成功、失败、部分失败和需要重试的真实结果；
- 数据库或索引未就绪时的受限导航和生成阻断。

页面不得提供任意路径选择器、任意数据库浏览、任意命令、任意 SQL、事实库一键清空或完整密钥回显。

### 4.2 履历库 `/profile`

- 列出 Experience，并按类型、时间和关键词提供基础查找；排序必须稳定；
- 创建和编辑表单覆盖当前 Experience 契约，字段校验与后端一致；
- 删除前明确展示对象并二次确认；成功后刷新后端状态；
- 保存后只展示 Experience 级汇总状态，例如“事实已同步、索引待重建、索引可用、处理失败”；
- PDF 上传 → 文本解析 → 经历提取 → 用户逐项检查/修改 → 保存 Experience 形成连续流程；
- 批量保存必须逐项显示成功、失败和未保存项，不能把部分失败显示为全部成功；
- 不展示或编辑 Fact 明细，不新增归档、回收站、版本历史或持久化个人 Profile。

### 4.3 生成工作台 `/`

- 输入本次姓名、电话、邮箱、所在地和 JD；身份信息不写入 Experience；
- 可以先调用 JD 分析并展示七字段结构化结果；
- 从 `GET /api/template/list` 选择系统模板；
- 调用唯一核心 `POST /api/resume/generate-docx`，展示提交中、生成中、成功或失败；不得虚构后端未提供的细分进度；
- 生成成功后展示文件名、模板、warnings、必要 build_meta 摘要和安全下载入口；
- 生成按钮防止重复提交。超时或失败后由用户明确重试，不自动制造重复 LLM 调用或重复文件；
- 下载只能使用后端返回的合法 artifact，不接受浏览器提交任意服务器文件路径。

## 5. 本版本不做

- 实际 DOCX 页面预览、PDF 导出、Draft/Revision、条目锁定、差异、回退和局部重新生成；
- 用户手工覆盖 SelectedEvidenceSet、内容预算、选材规则或 Fact 明细；
- 多 Provider、OpenAI-compatible Endpoint、跨供应商模型切换、Token/费用统计和质量评测后台；
- 归档、回收站、生成历史、持久化个人 Profile、OCR 和用户自定义模板；
- 新的召回权重、相关性算法、生成策略、个人总结、严格一页纸或像素级排版；
- 后台任务、断点恢复、任务取消、消息队列、分布式 Worker、自动更新和在线补丁；
- 普通用户零密钥 Stub 图形演示；
- 登录、多用户、云端同步、公网部署、生产监控和完整移动端适配；
- Firefox 发布验收和 macOS/Linux 便携发行包；现有源码入口不得被无理由破坏，但跨平台便携不是本版 PASS 条件。

## 7. 开发验证矩阵

### 7.1 首次设置、配置与安全

- 首次无配置、字段缺失、错误 Base URL、错误 Key、LLM 成功但 Embedding 失败、超时和供应商异常；
- 候选配置测试失败后旧可用配置保持有效；激活成功后新请求使用新快照；
- Embedding model/Base URL/fingerprint 改变后旧索引失效，重建前生成阻断，重建后恢复；
- Credential Manager 新增、读取、更新、删除、不可用和拒绝访问；失败时无明文配置降级；
- 配置读取不返回完整 Key；浏览器缓存、URL、日志、错误、诊断和构建产物不含 Key；
- 恶意 Origin、错误 Host、缺失/错误 CSRF 或启动会话令牌、非 loopback 绑定全部拒绝写操作；正常同源流程通过；
- XSS 字符串作为姓名、JD、Experience、模型错误输入时只按文本显示。

### 7.2 数据库、索引和资源生命周期

- 不存在的全新 SQLite 文件通过界面初始化；重复初始化幂等；
- V1.5.0 既有数据库先备份核对再迁移；备份、核对或 cleanup 失败时界面显示失败且整体非成功；
- status 覆盖缺 schema、无 Fact、PENDING、FAILED、fingerprint/维度错误、全部 VALID；
- rebuild 覆盖无 Key、部分失败、全部成功、重复执行和中途异常；retry 只处理允许的失败项；
- 迁移/重建/重试与生成并发时执行冻结的拒绝/排队语义，不破坏事实或索引；
- 正常、初始化失败、依赖失败、断言失败、异常、提前退出、重复 cleanup、句柄占用和 cleanup 自身失败均验证资源释放与非零失败；
- 薄 API 与 CLI 对相同隔离 fixture 得到等价状态和后置条件；页面不调用 shell。

### 7.3 履历与生成页面

- PDF 正常、空文本、错误类型、超限、解析失败和外部提取失败；
- 提取结果修改后保存；0/1/多项保存；部分失败逐项可见；重复点击不重复创建；
- Experience 列表空态、稳定排序、筛选、新增、编辑、删除取消、删除确认、后端冲突和刷新核对；
- CRUD 后 Fact reconciliation、Embedding 失效/清理和生成阻断继续满足 V1.5.0 契约；前端不展示虚构的 Fact 状态；
- 身份字段缺失留空，JD 无岗位、模板不存在、索引未就绪、LLM 错误、Renderer/文件写入失败均显式可见；
- 成功生成展示 warnings 和合法下载；重复提交、超时后重试、非法 artifact/path traversal 被阻断；
- 前端页面不调用已退出的 Markdown 主链或 internal 模板调试接口。

### 7.4 便携包与浏览器

- 干净 Windows x64 环境未安装 Python/Node 时，便携启动、首次设置、生成和退出通过；
- 路径包含空格、中文和较长目录名；便携目录移动后仍使用同一 runtime 数据边界；
- 首次启动、重复启动、已有实例、端口冲突、静态资产缺失/损坏、浏览器打开失败、后端启动失败；
- 正常退出、启动中退出、页面仍打开时退出、重复退出和异常退出后的再次启动；端口、进程、DB 句柄、锁和临时资源可核对；
- Chrome 与 Edge 覆盖三页主流程、刷新、前进后退、键盘可达、表单标签、错误关联、焦点和不只靠颜色表达状态；
- 便携包内容扫描确认无 `.env`、真实数据库/DOCX、API Key、用户名、绝对本机路径、缓存或开发临时文件。

### 7.5 V1.5.0 回归与证据边界

- 复跑所有仍适用的 V1.5.0 Fact/Embedding、迁移、两层选材、受约束改写、Builder、来源映射、旧实现退出和 Stub 隔离测试；

### 11.1 问题类别与不可变条件

第四轮已证明单独的 dispose、rmtree 和重复 cleanup 可以被报告，但完整运行器仍存在两类组合缺口：临时目录创建后的环境初始化尚在保护范围外；传播中的 `SystemExit(0)` 可以压过 cleanup 失败。第五轮必须按“测试进程资源生命周期”整体收口，并同时满足：

1. **导入无副作用**：仅导入任一验证脚本不得创建目录、覆盖环境、导入产品 `main` 或取得 engine；所有可变动作从显式 `main()` / runner 开始。
2. **取得即登记**：临时目录创建后立即登记清理责任；保存原 `RESUME_DATA_DIR` 状态后再覆盖；engine、client 或句柄一旦取得，必须在执行下一个可能失败的步骤前登记到 cleanup 状态。
3. **清理独立且可核对**：client/engine 释放、环境恢复和临时目录删除逐项执行，前一步失败不得阻止后一步；除捕获异常外，必须显式验证目录确实不存在，防止“rmtree 无异常但未删除”被判成功；重复 cleanup 幂等。
4. **唯一退出码仲裁**：业务返回、断言失败、普通异常、`SystemExit`、`KeyboardInterrupt` 和 cleanup 结果先归并，最后只执行一次进程退出。`SystemExit(None/0)` 不能绕过 cleanup；任一 cleanup 或后置条件失败都必须使最终退出码非零，原有非零失败不得被覆盖为成功。
5. **真实 runtime 不可触碰**：临时环境必须在导入任何产品模块前生效；所有场景运行前后真实 runtime 与相邻哨兵的存在性、mtime 和内容 hash 不变；调用前环境在退出时恢复。
6. **边界明确**：正常异常和可捕获的提前退出属于本契约；`os._exit`、强制结束进程和断电等无法执行 Python cleanup 的情形不作为本轮 PASS 条件，也不得声称已经覆盖。

两个脚本可以提取一个轻量测试专用 runner 以消除重复实现，但不得把测试状态引入产品模块、建立第三套 runtime 配置或新增版本分项文档。

### 11.2 必须可执行的双脚本矩阵

每个场景必须对两个脚本分别在独立子进程执行，并同时断言进程退出码、临时目录集合差异、环境恢复和真实 runtime/哨兵后置条件；不能只调用 `_cleanup()` 后根据返回值推断整个进程正确。

| 类别 | 必测场景 | 完成条件 |
|---|---|---|
| 导入边界 | 仅 import 脚本，不调用 `main()` | exit 0；无新目录、环境变化或产品模块副作用 |
| 正常与业务失败 | 原命令成功；至少一个 `check` 失败 / runner 返回非零 | 成功仅在断言与 cleanup 均通过时 exit 0；业务失败非零且零残留 |
| bootstrap 失败 | `mkdtemp` 自身失败；临时目录创建后环境设置失败；`import main` 失败 | 非零；未取得资源时不误删，已经创建的目录被清理；原环境恢复 |
| 部分资源取得 | engine 取得后后续依赖导入失败；TestClient/lifespan 进入失败 | 非零；已取得资源释放；零残留 |
| 普通与提前退出 | 普通异常、`KeyboardInterrupt`、`SystemExit(None/0/非零/字符串)` | 均执行 cleanup；只有原结果成功且 cleanup 成功才允许 exit 0 |
| cleanup 单项失败 | dispose 抛错；rmtree 抛错；rmtree 无异常但目录仍存在；环境恢复失败 | 继续尝试其余步骤；后置条件失败明确可见；最终非零 |
| 组合失败 | `SystemExit(0)` 分别叠加 dispose、rmtree、目录仍存在或环境恢复失败；业务非零叠加 cleanup 失败 | 最终始终非零，不丢失业务与 cleanup 两类诊断 |
| 重复与占用 | cleanup 连续调用；Windows 文件句柄占用导致首次删除失败，释放后重试 | 幂等；首次失败非零；释放后可清理；不误删相邻对象 |

失败注入驱动可以是仓库外临时脚本；若新增仓库内测试文件，必须是可持续回归的正式测试，不得写入本机绝对路径、真实数据或新的文档真源。
