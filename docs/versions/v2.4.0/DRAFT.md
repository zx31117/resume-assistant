# AI Career Resume Assistant V2.4.0 草稿：生成质量冻结与一页纸成品

> 文档角色：版本范围草稿，供 Product Owner 审核
> 状态：DRAFT，非开发指令，不改变当前版本状态
> 重写日期：2026-09-25
> 假定前置：V2.3.0 的账号、多用户隔离、PostgreSQL/pgvector、ApplicationCase、生成公共合同、
> 埋点和服务器 Alpha 已完成并通过独立验收
> 发布列车：V2.3.0（底座）→ V2.4.0（本版生成质量冻结）→ V3.0.0（免费多用户首发）
> 核心目标：在固定评测、真实 Word/PDF 渲染和人工验收下，把召回、润色、内容预算与排版闭合为
> 稳定的一页纸可投递成品；本版未通过，V3.0.0 不得首发

## 1. 版本判断

V2.4.0 是 V3.0.0 前最后一次允许系统性重塑生成内核的版本。它不是只调整 Prompt，也不是只把
Recall@K 做高；它必须证明“选什么、怎么写、写多少、如何排成一页、最终文件是否真实可投”形成
一个可复现闭环。

本版建立第一版 `Person Model × Job Model`，并冻结：

~~~text
JobModelSnapshot
→ EvidenceSelection
→ ResumeContentPlan
→ ResumeRevision
→ LayoutPlan
→ DOCX
→ Word 实际渲染与测量
→ PDF
→ 同源 Artifact 发布
~~~

浏览器助手、自动上传、模拟面试、多模板和完整高级编辑均可后移。它们不能占用生成质量硬门禁的
时间，也不能成为 V3.0.0 是否首发的前置条件。

## 2. 用户结果

受控 Beta 用户完成一次生成后，应直接得到：

1. 与目标岗位明显相关、不是通用经历堆叠的内容；
2. 所有表述均可追溯到当前账号允许的 Fact；
3. 没有虚构指标、占位符、重复 bullet、空章节、调试文字或未完成提示；
4. 一份在批准 Word 参考环境中恰好一页的 DOCX；
5. 一份由该 DOCX 转换、也恰好一页的 PDF；
6. 清晰、克制、专业的层级、间距、字体、强调和中英文混排；
7. 不需要用户大段重写即可用于真实投递的最终结果。

如果事实、页数或可读性无法同时满足，系统必须明确失败或请用户确认取舍，不能把两页、截断、隐藏
内容或极小字号文件标记为“可直接投递”。

## 3. Job Model v1

### 3.1 三层结构

~~~text
JobModelSnapshot
├── explicit_requirements     JD 明示
├── role_prior_requirements   岗位先验
└── company_context           公司/业务公开信息
~~~

| 来源 | 召回 | 排序 | 表达重点 | 可声称为招聘方硬要求 |
|---|---:|---:|---:|---:|
| JD 明示 | 是 | 是 | 是 | 是 |
| Role Prior | 是 | 是 | 是 | 否 |
| Company Context | 是 | 是 | 是 | 否 |
| 无来源模型推测 | 否 | 否 | 否 | 否 |

每条 Job Model 项保存来源类型、文本或 URL、采集时间、置信度、版本、适用范围和召回许可。联网材料
可能过期或错误，不能成为用户事实，也不能静默改变 JD 原文。

### 3.2 Role Profile 与 Company Context

- 首批 Role Profile 只覆盖 Product Owner 批准的高频岗位，包含同义词、能力维度、证据类型、
  召回词、边界、版本和审核状态；
- 无法识别岗位或 Profile 置信度不足时只使用 JD，不强套相近岗位；
- Company Context 只使用批准来源、缓存和 TTL，不建立无边界网络 Agent；
- 公司同名、部门或产品线不明确时显示不确定，不自动合并；
- Company Context 可补回文本相似度较低但业务相关的 Fact，只改变 emphasis，不改变 proposition；
- 来源失败、过期或冲突时退回 JD + Role Prior，并记录降级。

## 4. Person Model 与证据分层

### 4.1 Fact enrichment

确认 Fact 可生成 Embedding、fingerprint、能力/技能/行业/场景标签、关键词和通用摘要。所有派生数据
保存模型、Prompt、版本、来源和状态，可失效、可重建，不反向覆盖 Fact。

### 4.2 Stable / Adaptive Evidence

- `Stable Evidence`：多个相似岗位都成立、表达成熟且 Fact 未变化的基础内容；
- `Adaptive Evidence`：受当前 JD、Role Prior、Company Context 或用户补充影响，需要重选或重写。

缓存键至少覆盖 Fact revision/hash、Role Profile family、表达策略、Prompt 和模型版本。任何事实、
规则或版本不匹配都必须失效，不能为了速度复用旧文。

## 5. 召回质量冻结

### 5.1 候选与排序

候选信号可包括 JD 语义、Role Prior、Company Context、技能/行业/场景、经历类型、时间、来源质量、
事实状态和用户明确偏好。候选生成与最终排序分别记录，不能把“进入候选”冒充“最终选中”。

固定评测集至少覆盖：

- short / typical / long Career Memory；
- 完整、宽泛、缺失关键信息、噪声和反例 JD；
- 多岗位、多行业、旧经历、弱相关和高文本相似但业务无关的 Fact；
- Company Context 能补召回的正例与不应补召回的负例；
- 双账号、未归属旧数据和负向哨兵。

正式 PLAN 冻结 Recall@K、Precision@K、nDCG 或等价指标，以及岗位要求覆盖、用户保留率、回退率、
延迟、Embedding 调用和成本阈值。跨账号召回与未知 Fact 进入率始终为 0。

## 6. 润色与内容计划冻结

### 6.1 ResumeContentPlan

生成正文前必须先形成版本化 `ResumeContentPlan`，至少包含：

- 章节及顺序；
- 每个章节的价值目标和字符/视觉行预算；
- 候选 Fact 的优先级、必要性和预期表达角度；
- 重复主题与合并关系；
- 可移除的最低优先级内容；
- 目标语言和表达风格。

系统承担事实边界内的专业选择，不要求用户先理解模板、页数、密度或逐条锁定。用户的自然语言意见
可以影响下一版计划，但不能直接绕过事实来源和一页纸门禁。

### 6.2 ResumeRevision

- 润色只使用冻结 EvidenceSelection；
- 每个内容条目保存稳定 ID、section、text、`fact_refs`、来源 hash 和版本；
- 改变重点不能改变事实命题；
- 不得用套话、空泛评价或无来源数字填补材料不足；
- 重复、冗余、语法、标点、时态和中英文风格进入机械与人工评测；
- 修改产生新 revision，不原地覆盖已经发布的成品。

## 7. 一页纸与专业排版闭环

### 7.1 单一生产模板

V3.0.0 前只冻结一套稳定生产模板。模板至少版本化：

- 页面尺寸与页边距；
- 字体及批准替代字体；
- 标题、正文、日期、地点和联系方式层级；
- 全局字号、行距、段距、字距和 bullet 缩进；
- 关键词强调与 `RichTextSpan` 渲染；
- 中英文混排和长文本换行规则；
- 最小可读性下限。

多模板、自选字体、密度滑杆和逐条局部缩字不进入本版硬范围。

### 7.2 实际渲染是最终判据

字符数、估算宽度和预测页数只能用于生成前预算。最终判据必须来自批准 Word 参考环境实际打开或
转换该 DOCX 后得到的：

- DOCX 页数；
- PDF 页数；
- 每个内容条目的真实视觉行和溢出；
- 字体替代、断页、孤行、遮挡和不可见内容；
- DOCX/PDF 内容与 revision/hash 的同源关系。

浏览器 HTML 预览不能替代 Word/DOCX 实际渲染证据。

### 7.3 超页收敛顺序

若实际渲染超过一页，按固定顺序处理：

1. 删除同义重复和空泛修饰；
2. 压缩超长 bullet，保留动作、方法、结果和事实边界；
3. 合并相邻重复表达；
4. 缩减低优先级 Fact 的表达；
5. 移除当前岗位价值最低且非必要的 Fact；
6. 在批准下限内依次调整全局段距、行距、字距和字号；
7. 重新生成 DOCX、由 Word 渲染并测量 PDF；
8. 达不到一页且保持可读时明确失败或请求用户确认取舍。

不得静默裁切、隐藏、减少透明度、将单条文字缩到异常字号，或输出与预览不同的下载文件。

### 7.4 发布条件

只有同时满足以下条件，Artifact 才能进入 `READY`：

- 来源、事实和账号校验通过；
- DOCX 与 PDF 来自同一冻结 ResumeRevision/LayoutPlan；
- DOCX 与 PDF 均为一页；
- 无溢出、遮挡、空页、占位符和失败标记；
- 版式达到批准的最小可读性；
- 文件可打开、可下载，MIME/hash/页数与记录一致。

## 8. 信息缺口与事实回流

信息缺口使用 `PROPOSED → CONFIRMED / CURRENT_ONLY / REJECTED`：

1. 只在当前结果会显著改善时提问；
2. 说明需要该信息的原因并允许跳过；
3. 回答先服务当前 ApplicationCase；
4. 只有用户明确确认才能写回 Career Memory；
5. 冲突、低置信和模型补全不覆盖旧 Fact；
6. Job Model 与模型推测永远不能写入 Person Model。

## 9. 性能与可调参数

Fast Lane 可先完成岗位识别、高置信候选和可复用 Stable Evidence；Precision Lane 完成扩展召回、
rerank、信息缺口和 Adaptive Evidence。最终文件只从冻结最终快照生成，中间结果不成为第二真源。

性能门禁使用真实服务器的 P50/P95、cold/warm、缓存命中/未命中、模型调用、Token、成本和一页纸
收敛轮次。新增 Job Model、测量和压缩不得无上限串行叠加等待时间。

V3.0.0 后允许继续调优召回权重、top-k、阈值、Role/Company 内容、Prompt、模型、表达风格、内容
预算和批准范围内的全局版式参数；不得再改事实真源、核心对象关系、DOCX/PDF 同源和一页纸闭环。

## 10. 浏览器助手与其他非阻断研究

若核心质量 Gate 已完成且仍有容量，可继续验证：

| 能力 | 本版口径 |
|---|---|
| L0 手工复制 JD、下载和上传引导 | 保留完整回退路径 |
| L1 读取当前岗位并创建 ApplicationCase | 可选受控探针 |
| L2 用户确认后填充字段 | 可选受控研究 |
| L3 用户确认后上传文件 | 仅可行性研究 |
| L4 自动提交 | 明确禁止 |

这些能力未完成不阻断 V2.4.0 或 V3.0.0。模拟面试、开放题 Agent、多模板、OCR、BYOK、本地模型和
完整高级修订 UI 同样后移。

## 11. 埋点与证据

本版记录但不保存用户正文：

- 岗位捕获、ApplicationCase、首结果、最终文件和下载漏斗；
- 召回规则、模型/Prompt/模板/LayoutPlan 版本；
- Stable Evidence 命中、Adaptive Evidence 重算和缓存节省；
- 候选数、最终选择数、用户保留/重生成和反馈；
- DOCX/PDF 页数、超页原因、收敛动作和失败阶段；
- Token、成本、延迟、重试和资源；
- 测试/补贴行为与自然行为区分。

## 12. 三天实施顺序候选

| 阶段 | 重点 | 退出条件 |
|---|---|---|
| Day 1 | 冻结质量集、V2.3 基线、Job Model 与混合召回 | 新旧路线可重复比较，隔离/事实边界不退化 |
| Day 2 | ResumeContentPlan、润色、单一模板、Word 测量和超页闭环 | 代表性样本可稳定收敛为一页成品 |
| Day 3 | 真实模型/服务器/Word 纵切、人工盲评、性能与反证 | 所有硬 Gate 可复核，形成 V3 交接基线 |

任何时间不足都优先砍浏览器助手和非核心增强，不减少质量集、真实渲染、人工验收或反向用例。

## 13. 发布 Gate 候选

### 13.1 事实与相关性

- [ ] Role Prior/Company Context 不冒充 JD 明示要求或用户事实；
- [ ] 固定评测集证明召回相对 V2.3.0 基线达到批准阈值；
- [ ] 未知、无来源、过期和跨账号 Fact 进入最终结果为 0；
- [ ] 润色盲评/真实偏好提升，重复、套话和事实越界不增加；
- [ ] 信息缺口未经确认不进入长期 Career Memory。

### 13.2 一页纸与文件

- [ ] 所有成功样本的 DOCX/PDF 均恰好一页；
- [ ] 一页不是通过静默删除必要事实、裁切、隐藏或突破字号/行距下限实现；
- [ ] 长短履历、中英文混排、粗体、长文本和字体替代矩阵通过；
- [ ] 预览、DOCX、PDF 和下载绑定同一 ResumeRevision/LayoutPlan；
- [ ] Word 实际渲染、页数、溢出和同源证据可机械复核；
- [ ] Product Owner 对代表性真实岗位完成人工验收并达到批准阈值。

### 13.3 性能与回归

- [ ] 真实服务器/模型/Word 环境的 P50/P95、cold/warm 和成本不越过批准上限；
- [ ] V2.3.0 多用户隔离、备份恢复、埋点脱敏和关键不变量无回归；
- [ ] V2.2.0 渐进结果、预览、下载、失败恢复和任务连续性无回归；
- [ ] 浏览器助手未完成不影响以上结论，若交付则另做安全矩阵。

## 14. 正式 PLAN 前待冻结

1. 首批 Role Profile、Company Context 来源和固定质量集；
2. 召回、润色、人工盲评、延迟、成本和失败率阈值；
3. 单一生产模板、字体包、批准 Word 参考环境和 PDF 转换路线；
4. 最小字号、最小行距、最小字距、页边距和跨软件允许偏差；
5. ResumeContentPlan 与 LayoutPlan 的字段、状态和版本规则；
6. 超页收敛最大轮次、仍不满足时的用户交互与失败语义；
7. 代表性真实岗位人工验收样本、判分表和 Product Owner 签字方式；
8. V2.4.0 向 V3.0.0 交接的冻结基线、可调参数白名单和禁止大改合同；
9. 若仍做浏览器助手研究，其资源上限、站点范围和不阻断声明。

在范围、阈值、模板、参考环境和必要 Design Snapshot 获批前，本文不授权开发。
