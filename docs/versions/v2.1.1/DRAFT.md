## 2. 已确认优化项

### V211-UX-01 工作台跨页面切换必须保留当前任务进度

#### 当前问题

用户在工作台上传、解析、填写 JD、生成或查看结果期间切换到“我的经历”或开发者后台，再返回
工作台时，页面重新初始化，当前输入、阶段或生成进度不可见。这破坏任务连续性，也会让用户无法
判断后台任务是否仍在运行。

#### 目标行为

工作台的一次任务会话必须跨应用内路由切换保持，不能以工作台页面组件的挂载生命周期作为任务
生命周期。用户离开后再返回，应看到离开前的同一个任务，而不是新的初始页面。

至少覆盖以下状态：

1. 上传后的解析进行中与解析完成状态；
2. 已解析履历、身份摘要和尚未提交或已提交的 JD；
3. 生成进行中的同一 `operation_id`、已完成阶段、当前阶段和各阶段明细；
4. 用户离开期间任务完成时，返回后直接显示该任务的真实结果；
5. 用户离开期间任务失败时，返回后显示原任务的失败位置、保留输入和既有重试入口；
6. 已生成的预览、事实依据选择状态和 Word/PDF 下载入口，直到用户明确开始新任务。

#### 行为约束

- 路由切换不得取消、重新提交或复制后台任务，也不得触发第二次 LLM/API 调用；
- 返回工作台后的轮询、事件流恢复或状态查询必须继续绑定原 `operation_id`，并具备幂等/去重边界；
- 已完成阶段和历史明细继续可点击回看，当前阶段继续显示最新真实事件；
- 只有用户明确执行“开始新任务”或等价重置操作，才清空当前工作台任务；普通导航不得隐式重置；
- 不得为了页面恢复把 API Key、完整履历、完整 JD 或生成正文新增写入不受控的浏览器长期存储；
- 状态承载方式、前端状态库和组件拆分由 Development Agent 设计，但验收以外部行为为准。

#### 正向验收

对解析中、JD 已填写、生成中、生成完成、生成失败五类状态分别执行：

~~~text
进入工作台并建立当前任务
→ 记录任务/operation 身份、输入、当前阶段和已有明细
→ 切换到“我的经历”
→ 返回工作台
→ 再切换到开发者后台
→ 返回工作台
~~~

每次返回都必须保持同一任务身份、输入、阶段、明细和结果；后台调用次数不得增加。任务在用户
离开期间继续推进时，返回后应补齐真实进度，不得倒退、伪造或重新开始。

#### 反向验收

- 路由往返后出现初始欢迎页、空白 JD、阶段归零或结果丢失，失败；
- 同一用户操作产生第二个 operation、重复上传、重复生成或额外模型计费，失败；
- 已完成任务因轮询重连退回“生成中”，或失败任务被静默清空，失败；
- 单纯依赖页面不卸载、隐藏组件或写死 Mock 规避状态恢复，失败；
- 通过 `localStorage` 等长期保存敏感完整正文，却没有明确数据边界和清理规则，失败。

#### 当前范围边界

本项已确认要求**应用内页面切换**保持连续性。以下能力尚未由 Product Owner 确认，不得在正式
PLAN 中自动扩大范围：

- 浏览器手动刷新后的恢复；
- 关闭并重新启动 ResumeAssistant 后恢复未完成任务；
- 应用崩溃或系统重启后的断点续跑；
- 同时保留或运行多个生成任务；
- 在其他页面增加全局悬浮进度条、通知或后台任务中心。
